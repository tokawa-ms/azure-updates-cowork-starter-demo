# 更新を検索・比較する
1. 指定された ID 同士の比較なら、その ID を使う。候補の検索が必要な場合だけ search_azure_updates を使う。「この更新に関連する」依頼では、表示中の ID の本文も取得する。検索は英語のタイトル・製品名への文字列部分一致であり、意味検索ではない。日本語の依頼をそのまま keyword にせず、話題の短い英語の語を選ぶ。0件なら利用者が指定した製品・提供状況・期間の条件は維持し、keyword だけを短くするか省略して一度再検索する。再検索を利用者へ提案するだけで終了しない。再検索でも0件の場合は検索範囲と条件を明示し、全サイトに該当がないと断定しない。
2. 検索の items をすべて確認し、利用者が指定した話題、製品、提供状況、期間に合う ID を列挙する。先頭の1件だけで検索を終えない。検索の modifiedSince は更新日の下限であり、提供開始日や期間の上限ではない点に注意する。
3. 本文の説明・比較が必要な更新は最大3件を get_azure_update で取得する。対象が3件以下なら全件を取得する。表示中の1件を取得済みでも、残りの対象 ID の取得を省略しない。4件以上なら対象の一覧を省略せず、詳しく説明する3件と、一覧情報だけの未取得分を区別する。検索範囲も最新200件以内であり、全更新を網羅したとは言わない。
4. 取得結果に userNotice があれば、その全文を言い換えずに最終回答へ記載する。状態、時期、対象、利用者への影響を日本語で説明し、比較の依頼では表を使う。検索だけなら不要な比較を加えないが、各件が何の更新なのかを日本語の短い説明で示す。英語の原題は転載せず、日本語の短い見出しへ訳す。同じ製品名は冒頭に一度示せばよく、各項目は「更新ID: 日本語の見出し」「提供状況と変更点の日本語の説明」とする。Launched は「一般提供」、In preview は「プレビュー」と表す。
5. 未記載の情報は不明とし、対象の全 ID と公式 URL を添える。回答に含めた ID と対象の一覧を照合し、漏れがあれば完了の報告前に直す。
