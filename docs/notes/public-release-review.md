## 現行ファイルへの対応

デプロイ記録の実Web URL、個人名を含む共有リソース名、配置・相関ID、実イメージdigest、削除済みリソースの識別子を削除またはプレースホルダーに置き換えた。評価記録の実FoundryレポートURL、事前検証の実ACR名・配置ID、観測記録の実trace IDも公開資料から外した。社内ネットワーク事情の説明は、Blobダウンロードを必要としない設計の説明へ置き換えた。学習に必要な手順、結果、制約は残している。

## 公開前に必要な判断

過去の2コミットを含めて公開する場合は、実環境情報と作成者情報の公開可否を確認する。公開しない場合は、承認された方法で履歴を匿名化するか、確認済みのファイルだけで新しい公開用リポジトリの初回コミットを作る。元の履歴を保持したまま新しい修正コミットを足すだけでは、今回の指摘は解消しない。

コミット作成者の公開用IDは、GitHubのnoreplyアドレスなどを明示して設定する。履歴の書き換えや新しい公開用リポジトリの作成は、この確認作業では実施していない。

作業フォルダー全体のZIP配布は避ける。無視対象の`.azure`、`.artifacts`、`.scratch`、`eval/out`、ビルド・テスト出力には、実環境設定や応答・生成物が含まれ得る。配布には確認済みの管理対象ファイルだけを使い、GitHubへのpush後もSecret scanning / Push protectionと公開対象の履歴・添付成果物を確認する。

## 確認範囲と限界

初回監査は236個の管理対象ファイル、258個の一意な履歴blob、唯一のローカル参照`refs/heads/main`から到達できる2コミットを対象にした。監査中に追加された無視対象外ファイル7個も確認し、管理対象のWord・PowerPointテンプレート2個はXML、メタデータ、外部参照を確認した。無視対象6,346個はファイル名の一覧のみで、内容の監査はしていない。

並行して文書を更新したため、初回監査は不変の最終ツリーを保証するものではない。リモートだけにある履歴、到達不能オブジェクト・reflog、画像内の文字のOCR、第三者コンテンツの法的な再配布可否は対象外。外部のスキャンサービスへのアップロードや実環境への接続は行っていない。自動検出と手動確認には見逃しの可能性があり、「検出なし」は秘密情報が存在しないことの証明ではない。
